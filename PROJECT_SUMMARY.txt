================================================================================
PYTHON PACKET SNIFFER - PROJECT SUMMARY
================================================================================
A desktop network packet sniffer and traffic monitor built with Python, Scapy
and Flet, with a modular architecture designed for future security features.
Last updated: 2026-10-14

--------------------------------------------------------------------------------
1. OVERVIEW
--------------------------------------------------------------------------------
This application captures live network traffic on a selected network interface
and displays it in a real-time GUI. It supports capture filters (BPF syntax),
display filters, per-packet detail inspection, and export to CSV and PCAP
formats. The codebase is intentionally modular so that security analysis
(port-scan detection, malicious-traffic detection) can be added as a separate
subsystem without touching the capture or UI layers.

--------------------------------------------------------------------------------
2. FEATURES
--------------------------------------------------------------------------------
Capture
  - Enumerate and select a physical network interface (virtual/Npcap/loopback
    adapters are filtered out).
  - Start / stop live capture with safe toggle behaviour (buttons enable and
    disable correctly, no duplicate sniffer threads).
  - Optional BPF capture filter (e.g. "tcp", "udp port 53", "host 8.8.8.8").

Display
  - Live packet table (latest 500 matching rows displayed for performance).
  - High-contrast protocol badges, coloured row markers and selected-row highlighting.
  - Per-packet details panel (protocol, IPs, ports, MACs, length, info).
  - Display filter by protocol, IP address, or port.
  - Capture status, empty states, separate captured/matching/visible counts,
    and a Follow live control when inspecting an older packet.
  - Brief status, row-hover and detail-panel transitions; a small activity
    indicator is visible only while capture is running.

Export
  - CSV export of captured packet metadata.
  - PCAP export of raw packets (openable in Wireshark).
  - Format selected from a dropdown; native save-file dialog for location.
  - Export is only allowed after capture has been stopped.

--------------------------------------------------------------------------------
3. ARCHITECTURE
--------------------------------------------------------------------------------
Layered design with clear separation of concerns:

  UI layer (Flet)  ->  Controller  ->  Sniffer (Scapy)  ->  Parser  ->  Model
                                              |
                                        Exporters (CSV / PCAP)

  - The capture backend is decoupled from the UI via the PacketInfo dataclass,
    so the underlying engine (Scapy) could be swapped (e.g. PyShark) without
    breaking the UI.
  - Exporters share a common abstract base class, so new formats can be added
    by creating one new file.

--------------------------------------------------------------------------------
5. MODULE DESCRIPTIONS
--------------------------------------------------------------------------------
capture/interfaces.py
  Uses scapy.arch.windows.get_windows_if_list() and filters out virtual, QoS,
  loopback and miniport adapters to present only real NICs.

capture/sniffer.py
  Wraps Scapy's AsyncSniffer. Runs capture on a background thread, guards
  against double-start, and reports errors through a callback.

capture/parser.py
  Converts a raw Scapy packet into a PacketInfo object, extracting Ethernet,
  IPv4/IPv6, ARP, TCP/UDP, ICMP and DNS fields. Protocol label is refined from
  the most general layer to the most specific.

capture/controller.py
  Holds the sniffer instance and packet counter. On each packet it parses to
  PacketInfo and forwards both the PacketInfo and the raw packet to the app.
  Exposes is_running to let the UI know whether capture is active.

models/packet_info.py
  Dataclass holding: number, time, source, destination, protocol, length,
  mac_source, mac_destination, src_port, dst_port, info.

exporters/base.py
  BaseExporter (ABC) requiring export(packets, file_path) -> int and
  get_file_extension() -> str.

exporters/csv_exporter.py
  Writes packet metadata to a UTF-8 (BOM) CSV file.

exporters/pcap_exporter.py
  Writes raw Scapy packets to a .pcap file via scapy.wrpcap.

ui/main_view.py
  Builds the desktop layout: capture toolbar, display-filter controls, packet
  table, export actions and compact detail panel. Returns named controls used
  by app.py. ui/theme.py contains shared visual tokens.

utils/packet_filter.py
  Implements the display filter: matches protocol keywords (tcp/udp/icmp/arp/
  dns/ipv4/ipv6) or substring matches against source, destination and ports.

--------------------------------------------------------------------------------
6. DATA FLOW
--------------------------------------------------------------------------------
1. User selects an interface and clicks Start Capture.
2. app.py calls controller.start(interface, bpf_filter).
3. Controller creates a PacketSniffer, which starts Scapy AsyncSniffer.
4. Each captured packet -> controller.packet_received -> parse_packet -> PacketInfo.
5. Controller forwards (PacketInfo, raw_packet) to the app callback.
6. App appends to capture_packets (for display/CSV) and raw_packets (for PCAP),
   renders a row on the UI thread, and refreshes the counter.
7. On Stop, capture halts and the UI buttons reset.
8. On Export, the app validates that capture is stopped, asks the user for a
   location, and dispatches to the matching exporter.

7. TECH STACK
--------------------------------------------------------------------------------

  - uv                    (dependency and environment management)

--------------------------------------------------------------------------------
8. HOW TO RUN
--------------------------------------------------------------------------------
Prerequisites
  - Npcap installed (required by Scapy for packet capture on Windows).
  - Run as Administrator (raw packet capture needs elevated privileges).

Commands
  uv sync                       Install dependencies.
  uv run python app.py          Launch the application.
  uv run python test_exporters.py   Run the exporter test suite.

9. SECURITY FEATURES (ROADMAP / PLANNED)
--------------------------------------------------------------------------------
The next phase adds a dedicated security subsystem in a new top-level package
(security/) so detection logic stays isolated from capture and UI code.

Planned
  - Port-scan detection: track TCP SYN attempts per source host within a time
    window; raise an alert when one host probes many distinct ports/hosts.
  - Malicious traffic pattern detection: extensible rule/detector framework
    for suspicious behaviours beyond port scanning.
  - Alert model: a SecurityAlert dataclass (timestamp, type, severity, source,
    description) shared across detectors.
  - Alert UI: a separate alerts window plus a live alert notice/banner on the
    main window so the user is warned immediately.
  - Integrate alerts into the existing toolbar, packet list and detail layout.

Design principles
  - Each detector implements a common interface (mirroring exporters/base.py).
  - Detectors are pure functions of packet stream state -> easy to test.
  - UI consumes alerts through a callback, keeping detection UI-agnostic.
